Stafford v0.2.0 is the first release with the full conversation experience and the projects layer. A
colleague's work now renders as readable blocks instead of a raw terminal, a permission gate sits in
front of every file action, and you can hand a colleague a task and manage projects in one place. It
is still Windows only and unsigned, so treat it as early software.

## Features

### The live conversation

Open a colleague and its reply streams in as it is produced. The thinking, the tool calls, shell
output, file reads, and file edits render as readable blocks rather than raw terminal text, and a
finished turn re-renders the same way when you reopen it. A file edit shows as an inline diff through
the same viewer the task review uses.

[![01-conversation](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/01-conversation.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/01-conversation.png)

### A permission gate on every file action

Every file read, write, and edit a colleague makes goes through a gate before it runs, checked against
the project's rules and that colleague's own overrides. Anything set to ask pauses the turn on a banner
you approve or deny, with the exact path in front of you. Credential directories, Stafford's own data,
and secret files are denied by default.

[![02-permission-ask](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/02-permission-ask.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/02-permission-ask.png)

### Permissions you set per project

A configuration screen shows what a project allows, asks about, or denies, and lets you edit it in
place. Baseline rules apply to every colleague on the project, a locked default profile carries the
safe starting point, and per-colleague exceptions layer on top.

[![03-permissions](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/03-permissions.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/03-permissions.png)

### Tasks you hand out and review

Hand a colleague a task instead of a message. It runs bounded by a turn limit and a stop on no
progress, lands its work on its own git branch, and comes back for your review rather than marking
itself done. You see what it was asked, what it says it did, and the actual change as a hunk-level
diff, then approve it, send it back with a note, or fail it. Approving is the only route to done, and
only you can do it.

[![04-task-review](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/04-task-review.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/04-task-review.png)

### Answering a colleague's question

When a colleague needs a decision, it asks in the conversation and waits. The question and its choices
render as a form you answer inline, and your answer routes back as the tool result so the colleague
continues from your call.

[![05-ask-question](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/05-ask-question.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/05-ask-question.png)

### The Tasks board

One board shows every colleague's work grouped by state, so what needs you is answerable in one place
regardless of whose task it is. Columns cover waiting for you, working, assigned, approved, and failed,
and each card carries the colleague, the task, and its result branch.

[![06-tasks-board](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/06-tasks-board.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/06-tasks-board.png)

### The Projects tab

Manage projects in one place: create one, edit or repoint its working folder, delete it, and see which
colleagues are bound to it. A colleague bound to no project is parked and cannot work until you rebind
it, and a rebind starts a clean session on the new project rather than carrying the old context across.

[![07-projects](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/07-projects.png)](https://github.com/BENZOOgataga/StaffordAI/releases/download/v0.2.0/07-projects.png)

## Bug Fixes

- A colleague could be stranded showing Working with its reply lost when a write failed part way
  through a turn. The reply and its actions now survive that.
- The message box clears when a message sends, not when the reply lands, so it is ready for the next
  one.
- The working indicator stays visible through the real gap before a reply streams.
- Colleagues no longer flag an inherited skill they cannot load.

## Security

Much of this release is gate, containment, and isolation hardening.

- Secret files inside a project cannot be read. A `.env` and its variants, private keys, `.npmrc`,
  `.netrc`, and `credentials.json` are denied before the read runs, so a colleague cannot pull them into
  its context, while ordinary project files stay readable and it can still work. The no-secret templates
  (`.env.example`, `.env.sample`, `.env.template`, `.env.dist`) stay readable.
- Writes, the actions that pause for your approval, and reads outside the project folder go through the
  permission gate. A read inside the project folder does not reach the gate, since Claude Code allows its
  read-only tools inside the working directory without asking, so the secret files above are denied by
  the native rule instead. A symlink inside the project that points out of it is treated as an outside
  read and still goes through the gate.
- File paths are resolved to their real absolute form, with case folded through the platform and
  symlinks followed, before any comparison, so a path cannot reach a protected directory through a case
  difference or a symlink.
- The credential directories the configuration screen marks as protected are enforced on every call
  that carries a path.
- A colleague cannot point a project at Stafford's own directory. It is refused when you set it and
  again at spawn.
- A repository can no longer leak its own settings or other directories into a colleague's session.
  Each session loads only Stafford's settings, and a colleague's inherited user memory is blanked.
- The protected and secret-file floor now also applies to MCP tools and other tool categories, not
  only to plain reads and writes.
- The shell-command deny is best-effort. Claude Code decides for itself which commands it asks about,
  so treat a shell deny as a strong default rather than a hard boundary.

## Known limitations

- Windows only for now. The macOS code is written and compiles but is not verified on real hardware,
  so it is not shipped; it comes in a later release. Linux is written but unsupported, and the app
  refuses to start there rather than half working.
- The build is unsigned, so Windows SmartScreen warns on first launch. There is no installer and no
  auto-update yet.
- The shell deny is best-effort and reads are broad, as described in Security.
